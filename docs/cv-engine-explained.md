# CV Engine Code Explanation

The Computer Vision (CV) Engine is a Python FastAPI application responsible for analyzing camera feeds, counting adults and children, streaming the video, and posting telemetry data to the Laravel dashboard.

This document provides a detailed breakdown of what each Python file does, followed by an "Explain Like I'm 5" (ELI5) summary.

---

## 1. File Breakdown

### `config.py`
**Purpose:** Environment configuration and settings management.
- Uses `pydantic_settings` to load variables from the `.env` file with sensible defaults.
- Defines settings for the YOLO model (`CONFIDENCE_THRESHOLD`, `IOU_THRESHOLD`), tracking configuration, video source URL, and telemetry endpoints.
- Maps the integer class IDs (0 for Adult, 1 for Child) to the system logic.

### `tracker_manager.py`
**Purpose:** Memory management for detected objects.
- Contains the `TrackerManager` class, which keeps track of every unique object ID (assigned by YOLO's tracker) currently in the frame.
- Remembers the `last_seen` timestamp of every object.
- Includes a `clean_expired_ids()` method that purges objects from memory if they haven't been seen for a specific duration (default 30 seconds), ensuring people who leave the room are properly subtracted from the "current" count.

### `counter.py`
**Purpose:** Aggregates data and runs business logic.
- Maintains the four primary metrics: `current_adults`, `current_children`, `total_daily_adults`, and `total_daily_children`.
- Computes `current` counts by asking the `TrackerManager` how many active IDs are currently in the room.
- Provides the `is_overcrowded()` method, which calculates if the waiting room has exceeded the defined safety threshold for pediatric patients.

### `detector.py`
**Purpose:** The core vision processing engine.
- Loads the YOLOv26 model.
- Uses a **decoupled threading architecture**:
  - **Thread 1 (Capture):** Continuously drains the camera buffer to ensure the absolute latest frame is ready without lagging.
  - **Thread 2 (Inference):** Runs YOLOv26 object detection and tracking in the background.
- Contains the UI logic to draw bounding boxes, assign colors, and draw the tracking trails (the lines that follow moving people).
- Generates the final JPEG frames containing the boxes and text overlays via `get_frame_generator()`.

### `streamer.py`
**Purpose:** Video broadcasting.
- A lightweight FastAPI router that takes the JPEG frames generated by `detector.py` and serves them as a `multipart/x-mixed-replace` HTTP response. 
- This is what creates the MJPEG stream that the Laravel Dashboard embeds in the UI.

### `telemetry.py`
**Purpose:** Communicating with the Laravel Backend.
- Runs an asynchronous background loop using the `httpx` library.
- Every few seconds (defined by `TELEMETRY_INTERVAL_SECONDS`), it packages the metrics from `counter.py` into a JSON payload.
- Posts this JSON payload to the Laravel Restify API, which then broadcasts it to the Livewire dashboard via WebSockets.

### `main.py`
**Purpose:** The application entry point.
- Bootstraps the FastAPI application.
- Wires all the classes together (injecting the `TrackerManager` into the `Counter`, the `Counter` into the `Detector`, etc.).
- Uses FastAPI lifespan events to start the `TelemetryDispatcher` when the server starts and safely shut down all threads when the server stops.

## 2. ELI5 (Explain Like I'm 5)

Imagine you have a highly organized team working together at a security desk:

1. **The Rulebook (`config.py`)** 
   This is the instruction manual. It tells the team where the camera is, what an adult looks like, what a child looks like, and what phone number to call when they need to report the numbers.

2. **The Bouncer (`tracker_manager.py`)** 
   This person stands at the door and gives a unique sticky name tag to everyone who walks in. If they don't see someone with a specific name tag for 30 seconds, they assume that person went home and throws their name tag away.

3. **The Accountant (`counter.py`)** 
   This person constantly asks the Bouncer how many name tags are currently in the room. They write down the total number of adults and children on a whiteboard. If the room gets too full, they sound a red alarm.

4. **The Detective (`detector.py`)** 
   This is the fastest worker. They stare at the camera screen and draw boxes around people. Because watching the screen carefully takes time, they actually have two eyes: one eye never blinks and just watches the raw video, while the other eye draws the boxes. This stops the video from lagging.

5. **The TV Broadcaster (`streamer.py`)** 
   This person takes the video feed that the Detective drew on and broadcasts it live to a TV channel so the hospital administrators can watch it on their computers.

6. **The Messenger (`telemetry.py`)** 
   Every 3 seconds, this person looks at the Accountant's whiteboard, writes the numbers on a piece of paper, and runs as fast as they can to deliver it to the Hospital Boss (the Laravel Dashboard).

7. **The Boss (`main.py`)** 
   This is the manager who unlocks the building in the morning, tells everyone to start doing their specific jobs, and locks the building safely at night.
